# Broadcast Hub — TG Sender + Email Sender

Многопользовательское веб-приложение с двумя вкладками:

1. **TG Sender** — каждый пользователь подключает свой личный Telegram-аккаунт
   (по номеру телефона + коду, как при входе в обычный Telegram), вручную
   добавляет группы, выделяет их одной кнопкой и рассылает сообщение сразу во
   все группы. Сообщения можно удалять вручную (выделить → «Удалить
   выбранные») или автоматически — через 15 минут по умолчанию (настраивается
   перед отправкой).
2. **Email Sender** — каждый пользователь подключает свою почту (SMTP),
   вручную ведёт список брокеров (имя, фамилия, рабочие часы, email) и
   отправляет им письма — одному, выбранным или всем сразу.

У каждого зарегистрированного пользователя сайта — свой Telegram-аккаунт,
свои группы, своя почта и свой список брокеров. Данные разных пользователей
не пересекаются.

## ⚠️ Важно понимать перед запуском

- **Telegram.** Подключение личного аккаунта работает через официальный
  Telegram API (библиотека GramJS), а не через бота. Это даёт полную
  функциональность (отправка от вашего имени, удаление сообщений), но
  **массовая автоматическая рассылка с личного аккаунта может привести к
  ограничениям или блокировке номера со стороны Telegram**, если рассылки
  выглядят как спам. Используйте инструмент для отправки в группы, где
  аккаунт действительно состоит и является участником/админом, и не
  злоупотребляйте частотой отправки.
- **Хранение секретов.** Telegram-сессии и пароли от почты шифруются
  (AES-256-GCM) перед записью в базу, ключ — `ENCRYPTION_KEY` в `.env`. Тем не
  менее это ваша собственная инфраструктура — разместите сервер за HTTPS и
  ограничьте доступ к файлу `data.sqlite` и `.env`.
- **Это не облачный сервис** — вы разворачиваете и запускаете проект сами
  (на своём сервере/VPS). Автор кода (Claude) не хранит и не имеет доступа ни
  к каким аккаунтам или паролям.

## Установка

```bash
cd broadcast-hub
npm install
cp .env.example .env
```

Заполните `.env`:

1. `SESSION_SECRET` — любая длинная случайная строка.
2. `ENCRYPTION_KEY` — сгенерируйте командой:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
3. `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — получите бесплатно на
   https://my.telegram.org → **API development tools**. Это один общий ключ
   приложения для всего сайта (как у любого стороннего Telegram-клиента);
   каждый пользователь после этого входит своим собственным номером телефона.
4. `DEFAULT_AUTODELETE_MINUTES` — необязательно, по умолчанию уже 15.

Запуск:

```bash
npm start
```

Сайт поднимется на `http://localhost:3000` (или на порту из `PORT`).

## Как это работает

### Регистрация / вход
`POST /api/auth/signup`, `/api/auth/login`, `/api/auth/logout` — обычная
сессионная авторизация (логин/пароль, пароль хэшируется bcrypt).

### TG Sender
- `POST /api/telegram/login/start {phone}` — запрашивает код у Telegram.
- `POST /api/telegram/login/code {token, code}` — подтверждает код. Если у
  аккаунта включена двухфакторная защита, вернёт `{needsPassword: true}`.
- `POST /api/telegram/login/password {token, password}` — завершает вход.
- `GET /api/telegram/groups`, `POST /api/telegram/groups {identifier}`,
  `DELETE /api/telegram/groups/:id` — управление списком групп. `identifier`
  может быть `@username`, ссылкой-приглашением (`https://t.me/+xxxx`) или
  числовым ID группы (если аккаунт уже с ней знаком).
- `POST /api/telegram/send {groupIds, text, autoDeleteMinutes}` — рассылка.
  `autoDeleteMinutes: null` отключает авто-удаление для этого сообщения.
- `GET /api/telegram/messages` — журнал отправленных сообщений со статусом.
- `POST /api/telegram/messages/delete {messageDbIds}` — ручное удаление
  выбранных сообщений (аналог «select all → delete»).

Фоновый планировщик (`src/services/scheduler.js`) каждые 30 секунд проверяет,
не истёк ли таймер авто-удаления, и удаляет соответствующие сообщения в
Telegram.

### Email Sender
- `POST /api/email/connect` — сохраняет и проверяет SMTP-данные (host, port,
  secure, user, pass). Для Gmail/Outlook обычно нужен **пароль приложения**,
  а не обычный пароль аккаунта (из-за двухфакторной защиты).
- `GET/POST/PUT/DELETE /api/email/brokers` — CRUD списка брокеров (имя,
  фамилия, рабочие часы, email).
- `POST /api/email/send {brokerIds, subject, text}` — отправка письма
  выбранным или всем брокерам.

## Структура проекта

```
broadcast-hub/
  server.js                     точка входа
  src/
    db.js                       схема SQLite (better-sqlite3)
    crypto.js                   шифрование секретов
    middleware/auth.js          защита API по сессии
    routes/{auth,telegram,email}.js
    services/telegramManager.js вся логика GramJS (вход, группы, отправка, удаление)
    services/mailer.js          вся логика Nodemailer + брокеры
    services/scheduler.js       фоновое авто-удаление
  public/                       фронтенд (HTML/CSS/vanilla JS, без сборки)
```

## Продакшн-заметки

- Замените `express-session`'ную память по умолчанию на постоянное хранилище
  сессий (например, `connect-sqlite3` или Redis) — иначе при перезапуске
  сервера все пользователи будут разлогинены.
- Поставьте сайт за HTTPS (например, через Nginx + Let's Encrypt) — иначе
  логины/пароли/коды Telegram будут идти в открытом виде.
- Расширьте `services/telegramManager.js`, если нужна поддержка нескольких
  Telegram-сессий на одного пользователя или ограничение частоты отправки.
